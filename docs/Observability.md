# Dowe Pinless observability specification

The validation POC emits no operational event-log records. Any future event
source must use this allowlist and must fail closed if a field is not explicitly
approved.

## Allowed fields

- Event category: `service-start`, `service-stop`, `validation-result`,
  `enrollment-result`, or `storage-integrity-failure`.
- UTC timestamp generated by the event writer.
- Coarse result: `success`, `rejected`, `unavailable`, or `error`.
- Product/provider version.
- Non-reversible account correlation ID derived from a documented keyed hash;
  never the account name or SID itself.
- Numeric diagnostic detail codes that contain no raw protocol data.

## Prohibited fields

Never record TOTP values, recovery codes, TOTP seeds, DPAPI-protected blobs,
QR/otpauth URIs, passwords, PINs, account names, SIDs, raw IPC requests or
responses, authenticator enrollment output, or exception text that may contain
those values. User-entered text must not be logged.

## Retention and collection

Events should use the Windows Event Log with a bounded retention policy defined
by the installer. Collection is opt-in for diagnostics, and exported logs must
be reviewed for redaction before sharing. Failed writes must not block
validation or enrollment and must not trigger a fallback that writes secrets to
stdout, files, crash dumps, or telemetry.

## Test requirement

Before enabling operational events, add automated tests that construct every
event category with representative sensitive values and assert that serialized
output contains none of those values. The roadmap item remains open until
those tests and a review of the final event writer pass.
